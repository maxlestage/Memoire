# Memoire, Diesel and SeaORM

Diesel and SeaORM are the two most used ORMs in Rust. This page compares them with Memoire feature by feature, so you can pick the right tool, or move code from one to the other. It tries to be fair: each library is ahead somewhere.

## In one sentence each

- **Diesel**: a synchronous query builder that checks every query at compile time against a `schema.rs` generated from your database (async through the separate `diesel-async` crate). PostgreSQL, MySQL, SQLite.
- **SeaORM**: an async ORM built on SQLx, with entities generated by a CLI, `ActiveModel`s for changes and rich relation helpers. PostgreSQL, MySQL, SQLite.
- **Memoire**: an async ORM with a single `#[derive(Model)]` on your own struct, primary-key SQL rendered while the code compiles, and the same API on SQL and NoSQL: PostgreSQL, MySQL/MariaDB, SQLite, Redis, MongoDB and a pure-Rust in-memory engine that runs in WebAssembly.

## Feature by feature

| | Diesel | SeaORM | Memoire |
|---|---|---|---|
| Async | via `diesel-async` | yes | yes, every backend |
| Model definition | `table!` schema + struct derives | generated entity module (`Model`, `ActiveModel`, `Relation`...) | one `#[derive(Model)]` on your struct |
| Type-checked filters | yes, against the schema | partly (column enums, values checked at run time) | yes: `User::AGE.gt("18")` does not compile |
| SQL for primary-key CRUD | generated from the query types, prepared statements cached | built at run time | **rendered at compile time** for each dialect |
| PostgreSQL / MySQL / SQLite | yes | yes | yes |
| Redis, MongoDB | no | no | yes, same API |
| In-memory engine, WebAssembly | no | mock connection for tests | yes, a real engine with indexes and transactions |
| Joins | yes, typed | yes | yes, decoded into tuples |
| Relations without N+1 | `belonging_to` + `grouped_by` | `find_with_related`, `load_one`, `load_many`, `load_many_to_many` | `belonging_to`, `load_children`, `load_parent`, `load_via` |
| Relation declaration | `#[diesel(belongs_to)]` + `joinable!` | `Relation` enum + `Related` impls | none: read from `references = "table(col)"` |
| Partial update | `AsChangeset` struct | `ActiveModel` with `Set(...)` | `update_only(&db, (User::NAME, User::AGE))` |
| Bulk update / delete with filters | yes | yes | yes, with `increment`, `set_null`... |
| Multi-row insert | yes, returns rows on PG/SQLite | yes | yes, batched under each database's parameter limit |
| Upsert | `on_conflict` | `on_conflict` | `upsert` (by primary key) |
| Pagination | manual `limit`/`offset` | `paginate`, cursor pagination | `paginate` (count and page run concurrently) |
| Aggregates, `GROUP BY` | yes | yes | yes |
| Subqueries, self-joins (aliases) | yes | yes | not yet: use raw SQL |
| Composite primary keys | yes | yes | not yet: surrogate key + `unique` |
| Streaming results | `load_iter` | `stream` | not yet |
| Migrations | CLI, SQL `up`/`down` files | Rust migrations with `up`/`down` | Rust or SQL, forward only, in transactions |
| Normalised errors | `DatabaseErrorKind` (unique, foreign key...) | `SqlErr` (unique, foreign key) | `UniqueViolation`, `NotFound`, `Constraint`, `Conflict`... on every backend, NoSQL included |
| Code generation from an existing database | yes (`diesel print-schema`) | yes (`sea-orm-cli generate entity`) | no |

## Going from Diesel to Memoire

| Diesel | Memoire |
|---|---|
| `users::table.find(1).first::<User>(&mut conn)` | `User::get(&db, 1).await?` |
| `users::table.filter(users::age.gt(18)).load::<User>(&mut conn)` | `User::query().filter(User::AGE.gt(18)).all(&db).await?` |
| `diesel::insert_into(users::table).values(&new_user).execute(&mut conn)` | `user.insert(&db).await?` (the id is written back) |
| `diesel::update(&user).set(&changes).execute(&mut conn)` | `user.update_only(&db, (User::NAME, User::AGE)).await?` |
| `Post::belonging_to(&users).load::<Post>(&mut conn)?.grouped_by(&users)` | `users.load_children::<Post>(&db).await?` |
| `conn.transaction(\|conn\| ...)` | `let tx = db.begin().await?; ...; tx.commit().await?` |

## Going from SeaORM to Memoire

| SeaORM | Memoire |
|---|---|
| `user::Entity::find_by_id(1).one(&db)` | `User::find(&db, 1).await?` |
| `user::Entity::find().filter(user::Column::Age.gt(18)).all(&db)` | `User::query().filter(User::AGE.gt(18)).all(&db).await?` |
| `active_model.insert(&db)` | `user.insert(&db).await?` |
| `let mut am: user::ActiveModel = u.into(); am.name = Set(..); am.update(&db)` | `u.name = ..; u.update_only(&db, User::NAME).await?` |
| `user.find_related(post::Entity).all(&db)` | `Post::belonging_to(&user).all(&db).await?` |
| `users.load_many(post::Entity, &db)` | `users.load_children::<Post>(&db).await?` |
| `posts.load_many_to_many(tag::Entity, post_tag::Entity, &db)` | `posts.load_via::<PostTag, Tag>(&db).await?` |
| `user::Entity::find().paginate(&db, 20).fetch_page(1)` | `User::query().paginate(&db, 2, 20).await?` (pages start at 1) |

## Which one to choose

- **Diesel** when you want the strongest compile-time guarantees against the real schema and the most mature SQL coverage (subqueries, composite keys, custom SQL types), and synchronous code suits you.
- **SeaORM** when you want async with a large ecosystem around it (code generation from an existing database, GraphQL, admin tools) and its entity style suits you.
- **Memoire** when you want async with the least boilerplate (your own struct, one derive), the same code on SQL, NoSQL and in the browser, tests that run on the in-memory engine without a database server, and normalised errors.
