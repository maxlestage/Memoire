# Models

A model is a Rust struct that describes one database table. This page covers everything `#[derive(Model)]` understands: table names, primary keys, column attributes, supported Rust types, the items the macro generates for you, and `#[derive(FromRow)]` for custom result rows.

## Your first model

```rust
use memoire_orm::prelude::*;

#[derive(Model, Debug, Clone, PartialEq)]
#[memoire(table = "users")]
pub struct User {
    #[memoire(primary_key, auto_increment)]
    pub id: i64,
    #[memoire(unique)]
    pub email: String,
    #[memoire(index)]
    pub name: String,
    pub age: Option<i32>,
    pub active: bool,
}
```

Each field becomes a column with the same name. Here is what this produces on SQLite:

```sql
CREATE TABLE "users" (
    "id" INTEGER PRIMARY KEY,
    "email" TEXT NOT NULL UNIQUE,
    "name" TEXT NOT NULL,
    "age" INTEGER,
    "active" INTEGER NOT NULL
);
CREATE INDEX "idx_users_name" ON "users" ("name");
```

Notice that `age` has no `NOT NULL`: it is an `Option<i32>`, so it accepts `NULL`. Every other column is required.

### What the derive generates

`#[derive(Model)]` writes all of this for you at compile time:

| Generated item | Example | Used for |
|---|---|---|
| An implementation of the `Model` trait | `User::query()`, `user.insert(&db)`, `User::find(&db, 1)` | Every database operation |
| An implementation of `FromRow` | (used internally) | Turning a database row back into a `User` |
| One typed column constant per field | `User::ID`, `User::EMAIL`, `User::AGE` | Type-safe filters, ordering and projections |
| A static table description with pre-rendered SQL | `User::SCHEMA` | Creating tables and running primary-key operations without building SQL at run time |

### Requirements

- The struct must have **named fields** (`struct User { ... }`). Tuple structs, unit structs and enums cannot be models.
- The struct **cannot be generic** (`struct Wrapper<T>` is rejected).
- Every stored field type must be supported (see the type table below).
- The model must be `Send + Sync + 'static`, which ordinary structs of owned data always are.

> **Note** `#[derive(Model)]` already implements `FromRow`. Do not add `#[derive(FromRow)]` on the same struct, or the two implementations will conflict.

## The table name

Set the table name with the struct attribute `table`:

```rust
#[derive(Model)]
#[memoire(table = "blog_posts")]
pub struct BlogPost {
    pub id: i64,
    pub title: String,
}
```

Without it, the table name is the struct name in `snake_case`, **without** pluralisation:

| Struct | Default table name |
|---|---|
| `User` | `user` |
| `BlogPost` | `blog_post` |
| `HTTPRequest` | `http_request` |

> **Tip** Always writing `#[memoire(table = "...")]` makes your schema explicit and lets you rename the struct later without touching the database.

## Using Memoire through another crate

`#[derive(Model)]` writes code that refers to `::memoire_orm`. A framework that re-exports Memoire (such as [Paquets](https://github.com/maxlestage/Paquets), where it is `paquets::orm`) tells the derive where to find it with the struct attribute `crate`, so your project does not need its own `memoire-orm` dependency:

```rust
#[derive(paquets::orm::Model)]
#[memoire(crate = "paquets::orm", table = "notes")]
pub struct Note {
    pub id: i64,
    pub text: String,
}
```

## Primary keys

Every model needs exactly one primary key. It identifies a row and is what `find`, `get`, `update`, `delete` and `upsert` use.

There are two ways to choose it:

1. Mark a field with `#[memoire(primary_key)]`.
2. Or simply name a field `id`: with no explicit `primary_key` anywhere, a field called `id` becomes the primary key.

### Auto-increment keys

With `auto_increment`, the database generates the key when you insert a row. The value in your struct is ignored on insert, and the generated value is written back into it:

```rust
#[derive(Model, Debug)]
#[memoire(table = "notes")]
pub struct Note {
    #[memoire(primary_key, auto_increment)]
    pub id: i64,
    pub text: String,
}

async fn demo(db: &MemoryDb) -> memoire_orm::Result<()> {
    let mut note = Note { id: 0, text: "hi".into() };
    note.insert(db).await?;
    assert_eq!(note.id, 1); // generated by the database
    Ok(())
}
```

Auto-increment keys must be `i16`, `i32` or `i64`.

### The implicit `id` rule

Here is exactly how Memoire decides, so there are no surprises:

| Field declaration | Primary key? | Auto-increment? |
|---|---|---|
| `id: i64` (no attribute anywhere in the struct) | yes (implicit) | **yes** (implicit, because it is an `i16`/`i32`/`i64` named `id`) |
| `id: String` or `id: uuid::Uuid` (no attribute) | yes (implicit) | no |
| `#[memoire(primary_key, auto_increment)] id: i64` | yes | yes |
| `#[memoire(primary_key)] id: i64` | yes | **no**: you chose the key explicitly, so add `auto_increment` if you want generated ids |
| `#[memoire(auto_increment = false)] id: i64` | yes (implicit) | no |
| `#[memoire(primary_key)] slug: String` | yes | no |

> **Warning** `#[memoire(primary_key)] id: i64` alone is *not* auto-increment. If you insert several rows with `id: 0`, the second insert fails with a unique violation. Add `auto_increment`, or drop the attribute and rely on the implicit rule.

### Natural keys

A key does not have to be a number. Here the slug is the key, and you provide it yourself:

```rust
#[derive(Model, Debug, Clone)]
#[memoire(table = "tags")]
pub struct Tag {
    #[memoire(primary_key)]
    pub slug: String,
    pub label: String,
}

async fn natural(db: &MemoryDb) -> memoire_orm::Result<()> {
    let mut rust = Tag { slug: "rust".into(), label: "Rust".into() };
    rust.insert(db).await?;
    let found = Tag::get(db, "rust").await?; // look up by the string key
    assert_eq!(found.label, "Rust");
    Ok(())
}
```

## Column attributes

Attributes go in `#[memoire(...)]` above a field. You can combine several, separated by commas.

| Attribute | Example | Effect |
|---|---|---|
| `primary_key` | `#[memoire(primary_key)]` | This field is the primary key (alias: `id`) |
| `auto_increment` | `#[memoire(primary_key, auto_increment)]` | The database generates the key (alias: `auto`; `auto_increment = false` disables the implicit rule) |
| `unique` | `#[memoire(unique)]` | Adds a `UNIQUE` constraint; duplicates fail with `Error::UniqueViolation` |
| `index` | `#[memoire(index)]` | Creates an index named `idx_<table>_<column>` |
| `column` | `#[memoire(column = "e_mail")]` | Stores the field under another column name (alias: `rename`) |
| `sql_type` | `#[memoire(sql_type = "VARCHAR(120)")]` | Overrides the SQL type used in `CREATE TABLE` |
| `default` | `#[memoire(default = "0")]` | Adds `DEFAULT <SQL expression>` to the column |
| `references` | `#[memoire(references = "users(id)")]` | Adds a foreign key; `"users.id"` is accepted too |
| `on_delete` | `#[memoire(references = "users(id)", on_delete = "cascade")]` | Action when the referenced row is deleted |
| `on_update` | `#[memoire(references = "users(id)", on_update = "cascade")]` | Action when the referenced key changes |
| `skip` | `#[memoire(skip)]` | The field is not stored at all |

Here is a model that uses most of them:

```rust
#[derive(Model, Debug, Clone)]
#[memoire(table = "posts")]
pub struct Post {
    #[memoire(primary_key, auto_increment)]
    pub id: i64,
    #[memoire(references = "users(id)", on_delete = "cascade", index)]
    pub author_id: i64,
    #[memoire(sql_type = "VARCHAR(200)")]
    pub title: String,
    #[memoire(column = "body_markdown")]
    pub body: String,
    #[memoire(default = "0")]
    pub views: i32,
    #[memoire(skip)]
    pub rendered_html: Option<String>,
}
```

On PostgreSQL this creates:

```sql
CREATE TABLE "posts" (
    "id" BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "author_id" BIGINT NOT NULL,
    "title" VARCHAR(200) NOT NULL,
    "body_markdown" TEXT NOT NULL,
    "views" INTEGER NOT NULL DEFAULT 0,
    FOREIGN KEY ("author_id") REFERENCES "users" ("id") ON DELETE CASCADE
);
CREATE INDEX "idx_posts_author_id" ON "posts" ("author_id");
```

### `unique` and `index`

- `unique` makes the database reject a second row with the same value. Memoire reports it as `Error::UniqueViolation { table, column }` on every backend. A `unique` column is automatically indexed by the database.
- `index` speeds up filters, joins and sorting on that column. Use it on columns you search by often, such as foreign keys. SQL databases and MongoDB create a real index; the in-memory engine and Redis ignore it.

### `column` (rename)

The Rust field and the column can have different names. The typed constant keeps the *field* name (`Post::BODY`), but the SQL uses the column name (`"body_markdown"`). It is also the way to use a Rust keyword as a column name:

```rust
#[derive(Model)]
#[memoire(table = "items")]
pub struct Item {
    pub id: i64,
    pub r#type: String,                 // column "type", constant Item::TYPE
    #[memoire(column = "item_kind")]
    pub kind: String,                   // column "item_kind", constant Item::KIND
}
```

### `sql_type`

`sql_type` replaces the SQL type written in `CREATE TABLE`. It does not change how values are converted in Rust, so pick a type compatible with the field. The same text is used for every SQL database, so prefer portable types such as `VARCHAR(120)`. Redis and MongoDB, which have no `CREATE TABLE`, ignore it.

### `default`

`default` is copied verbatim into the column definition, so write a SQL expression: `"0"`, `"'draft'"` (with SQL quotes for text) or `"CURRENT_TIMESTAMP"`.

> **Note** Memoire's own `insert` always sends every field, so the default is never used by `insert`. It matters for rows inserted by raw SQL or other programs, and for filling existing rows when you add a column in a migration. The in-memory engine, Redis and MongoDB ignore it.

### `references`, `on_delete` and `on_update`

`references = "table(column)"` (or `"table.column"`) declares a foreign key. `on_delete` and `on_update` accept `cascade`, `restrict`, `no_action`, `set_null` and `set_default` (case does not matter). They are only allowed together with `references`.

| Backend | Foreign keys enforced? |
|---|---|
| PostgreSQL | Yes |
| SQLite | Yes (Memoire turns on `PRAGMA foreign_keys`) |
| MySQL / MariaDB | Yes |
| In-memory engine, Redis, MongoDB | No: the constraint is accepted but not checked, and `cascade` does nothing |

Create the referenced table first (`users` before `posts`). See [Joins & relations](relations) for how to query related tables.

### `skip`

A skipped field is not a column: it is not stored, not selected, and gets `Default::default()` when a row is loaded. Its type must therefore implement `Default`. Use it for caches or computed values. A skipped field cannot carry other column attributes.

## Supported Rust types

Wrap any type in `Option<T>` to make the column nullable.

| Rust type | Feature | PostgreSQL | SQLite | MySQL |
|---|---|---|---|---|
| `bool` | | `BOOLEAN` | `INTEGER` (0 or 1) | `BOOLEAN` |
| `i8`, `i16`, `u8` | | `SMALLINT` | `INTEGER` | `SMALLINT` |
| `i32`, `u16` | | `INTEGER` | `INTEGER` | `INT` |
| `i64`, `u32` | | `BIGINT` | `INTEGER` | `BIGINT` |
| `f32` | | `REAL` | `REAL` | `FLOAT` |
| `f64` | | `DOUBLE PRECISION` | `REAL` | `DOUBLE` |
| `String` | | `TEXT` | `TEXT` | `TEXT`, or `VARCHAR(255)` when keyed |
| `Vec<u8>` | | `BYTEA` | `BLOB` | `BLOB`, or `VARBINARY(255)` when keyed |
| `uuid::Uuid` | `uuid` | `UUID` | `TEXT` | `CHAR(36)` |
| `chrono::NaiveDateTime` | `chrono` | `TIMESTAMP` | `TEXT` | `DATETIME(6)` |
| `chrono::DateTime<Utc>` | `chrono` | `TIMESTAMPTZ` | `TEXT` | `DATETIME(6)` |
| `chrono::NaiveDate` | `chrono` | `DATE` | `TEXT` | `DATE` |
| `chrono::NaiveTime` | `chrono` | `TIME` | `TEXT` | `TIME(6)` |
| `serde_json::Value` | `json` | `JSONB` | `TEXT` | `JSON` |
| `Json<T>` (any `serde` type) | `json` | `JSONB` | `TEXT` | `JSON` |

"Keyed" means the column is a primary key, `unique`, `index` or `references` column (MySQL cannot index an unbounded `TEXT` column).

Auto-increment keys get special DDL: `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` on PostgreSQL, `INTEGER PRIMARY KEY` on SQLite and `BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY` on MySQL (for an `i64` key).

Redis and MongoDB have no column types: Redis stores each row as a JSON object and MongoDB as a BSON document. Their pages describe how each Rust type is stored ([Redis](redis), [MongoDB](mongodb)); every type in the table above is supported by all six backends.

> **Note** `u64`, `usize`, `i128` and `char` are not supported: there is no portable SQL type for them. Use `i64` (or `String` for `char`). Why `i64`? Because it is the largest integer every supported database stores natively.

### JSON columns

`Json<T>` stores any type that implements `serde::Serialize` and `serde::Deserialize`:

```rust
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug, Clone, PartialEq)]
pub struct Settings {
    pub theme: String,
    pub notifications: bool,
}

#[derive(Model, Debug, Clone)]
#[memoire(table = "profiles")]
pub struct Profile {
    pub id: i64,
    pub settings: Json<Settings>,
    pub extra: Option<serde_json::Value>,
}
```

`Json<T>` dereferences to `T`, so `profile.settings.theme` works directly, and you build one with `Json(Settings { ... })`.

### Custom column types

You can store your own types, such as an enum, by implementing four small conversion traits. Here a `Status` enum is stored as text:

```rust
use memoire_orm::prelude::*;
use memoire_orm::{ColumnType, FromValue, IntoValue, SqlType, ToValue};

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum Status {
    Draft,
    Published,
}

impl SqlType for Status {
    type Base = Status; // the type used in typed comparisons
    const KIND: ColumnType = ColumnType::Text; // stored as TEXT
}

impl ToValue for Status {
    fn to_value(&self) -> Value {
        let text = match self {
            Status::Draft => "draft",
            Status::Published => "published",
        };
        Value::Text(text.to_owned())
    }
}

impl IntoValue for Status {
    fn into_value(self) -> Value {
        self.to_value()
    }
}

impl FromValue for Status {
    fn from_value(value: Value) -> memoire_orm::Result<Self> {
        match value.as_str() {
            Some("draft") => Ok(Status::Draft),
            Some("published") => Ok(Status::Published),
            _ => Err(Error::conversion(format!("unknown status: {value}"))),
        }
    }
}

#[derive(Model, Debug, Clone)]
#[memoire(table = "articles")]
pub struct Article {
    pub id: i64,
    pub title: String,
    pub status: Status,
}

async fn published(db: &MemoryDb) -> memoire_orm::Result<Vec<Article>> {
    Article::query().filter(Article::STATUS.eq(Status::Published)).all(db).await
}
```

The comparison `Article::STATUS.eq(Status::Published)` is still type-checked: passing a string there would not compile.

## Typed column constants

For every stored field, the derive adds an associated constant named after the field in `UPPER_SNAKE_CASE`:

| Field | Constant | Type |
|---|---|---|
| `id: i64` | `User::ID` | `Column<User, i64>` |
| `email: String` | `User::EMAIL` | `Column<User, String>` |
| `age: Option<i32>` | `User::AGE` | `Column<User, Option<i32>>` |
| `r#type: String` | `Item::TYPE` | `Column<Item, String>` |

A `Column<M, T>` knows its table, its name and its Rust type, so the compiler checks how you use it:

- comparisons accept only values of the column's type (`User::AGE.gt(18)`, not `User::AGE.gt("18")`);
- text helpers such as `contains` exist only on text columns;
- `update_many().set(...)` accepts only columns of the model being updated;
- `set_null` accepts only `Option` columns;
- a misspelled constant (`User::EMIAL`) is a compile error.

`User::EMAIL.name()` returns the column name (`"email"`). The full list of what you can do with columns is in [Query builder](queries).

## The table schema and compile-time SQL

Every model exposes `Model::SCHEMA`, a `&'static TableSchema` built at compile time. It contains the table name, the columns and, for each SQL dialect, the ready-made statements used for primary-key operations:

```rust
use memoire_orm::prelude::*;

fn inspect() {
    let schema = User::SCHEMA;
    println!("table: {}", schema.name);
    println!("primary key: {}", schema.pk().name);
    for column in schema.columns {
        println!("- {} (nullable: {})", column.name, column.nullable);
    }

    let pg = schema.sql(Dialect::Postgres);
    println!("{}", pg.insert);
    println!("{}", pg.find);
}
```

```text
table: users
primary key: id
- id (nullable: false)
- email (nullable: false)
- name (nullable: false)
- age (nullable: true)
- active (nullable: false)
INSERT INTO "users" ("email", "name", "age", "active") VALUES ($1, $2, $3, $4) RETURNING "id"
SELECT "users"."id", "users"."email", "users"."name", "users"."age", "users"."active" FROM "users" WHERE "users"."id" = $1
```

`TableSchema::sql(dialect)` returns a `StaticSql` with seven fields: `columns`, `select`, `find`, `insert`, `update`, `delete` and `upsert`. Because these strings are constants baked into your binary, `User::find`, `user.insert`, `user.update`, `user.delete` and `user.upsert` never build SQL at run time.

To see the `CREATE TABLE` statements for a dialect, use `memoire_orm::sql::create_table`:

```rust
use memoire_orm::prelude::*;

fn print_ddl() {
    for statement in memoire_orm::sql::create_table(User::SCHEMA, Dialect::Postgres, false) {
        println!("{statement};");
    }
}
```

The last argument adds `IF NOT EXISTS` when `true`.

## Custom result rows with `#[derive(FromRow)]`

Sometimes a query returns something that is not a whole model: a report, a few columns, the result of raw SQL. `#[derive(FromRow)]` turns any struct with named fields into a row type:

```rust
use memoire_orm::prelude::*;

#[derive(FromRow, Debug)]
pub struct AuthorStats {
    pub author_id: i64,
    pub posts: i64,
    pub total_views: Option<i64>,
}

async fn stats(db: &MemoryDb) -> memoire_orm::Result<Vec<AuthorStats>> {
    Post::query()
        .group_by(Post::AUTHOR_ID)
        .select_exprs([Post::AUTHOR_ID.expr(), count_all(), Post::VIEWS.sum()])
        .all(db)
        .await
}
```

Columns are decoded **by position**, in the order the fields are declared: the first selected value goes into the first field, and so on. Names are not compared, which keeps decoding fast but means the order must match your `SELECT`. `#[memoire(skip)]` works here too.

`FromRow` is also implemented for scalars (`i64`, `String`, ...), `Option` of scalars, `Value`, and tuples of up to 8 elements, so for small results a tuple is often enough: `Vec<(i64, String)>`.

## Limitations

| Not supported | What to do instead |
|---|---|
| Composite primary keys (two `primary_key` fields) | Add a surrogate `id` key and a `unique` column, or create a composite constraint with a SQL [migration](migrations) |
| Generic structs, tuple structs, enums as models | Use a plain struct with named fields |
| `u64`, `usize`, `i128` fields | Use `i64` |
| Automatic schema diffing | Write [migrations](migrations) |
